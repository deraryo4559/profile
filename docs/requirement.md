# Profile Site Requirement

更新日: 2026-05-09

## 1. 背景

`profile` は、`my-portfolio` とは別リポジトリで管理する公式プロフィールサイトである。

- リポジトリ: `https://github.com/deraryo4559/profile.git`
- 公開想定URL: `https://ryo-onodera.com/profile/`
- 技術スタック: Vite, React, TypeScript, Tailwind CSS
- 位置づけ: 作品集そのものではなく、人物理解、経歴確認、仕事として相談できること、直近情報、外部リンクをまとめる公式プロフィールハブ

## 2. 今回の改訂方針

前回の画像生成案は、手描き風装飾、ステッカー、カラフルなカード、キャラクター要素が強く、親しみやすさはある一方で、プロフィールサイトとしての信頼感や商業的な完成度が弱く見えた。

今後のトップページは、以下の方向へ切り替える。

1. モダンで信頼感のあるプロフィールサイトにする
   - 学生らしい親しみやすさは残しつつ、軽すぎるポップ表現を避ける。
   - 仕事を依頼できる人として、落ち着き、整理力、実績感が伝わる見た目にする。
2. 商業的なポートフォリオとして見せる
   - 「できること」を単なるサービス一覧ではなく、WORKとして実績・役割・成果と結びつけて見せる。
   - 撮影、AI/開発、研究支援を、仕事として相談できる活動領域に整理する。
3. トップページの構成を絞る
   - セクション数を増やしすぎず、`Profile`, `WORK`, `NEWS`, `LINK` の4セクションで構成する。
   - `Services`, `Achievements`, `Contact CTA` のようなLP的な分割はトップページでは行わない。
4. 装飾よりも編集感を重視する
   - カードを大量に並べるより、余白、タイポグラフィ、写真、実績リストで見せる。
   - AIっぽい未来感や過剰なグラデーションではなく、人が設計した商業サイトの密度にする。

## 3. 参考サイトから取り入れる方向性

主な参考サイト:

- どいせな ポートフォリオサイト
  - https://doisena.jp/

参考にする点:

- 白基調で余白が広い。
- タイポグラフィが強く、英字見出しと日本語本文のバランスがよい。
- `work`, `profile`, `news`, `contact` のように、情報構造がシンプルで迷いにくい。
- 作品・実績が商業案件として見える。
- 親しみやすさはあるが、子どもっぽくない。
- イラストや写真があっても、装飾ではなく本人の仕事や世界観を伝える役割を持っている。
- 「simple, clear, cool, design-fit」という印象に近い。

参考にしない点:

- レイアウト、ロゴ、イラスト、配色、細部のUIをそのままコピーしない。
- どいせな氏はイラストレーターのポートフォリオなので、写真・AI・研究を扱う本サイトでは、よりプロフィールと相談導線を強める。

### 3.1 採用デザイン案

今回生成された `D / Modern Pop` 案を、トップページデザインの採用ベースとする。

採用する要素:

- 白基調の背景に、黒い太字タイポグラフィを強く効かせる。
- Headerは、左にROロゴ、右に `PROFILE`, `WORK`, `NEWS`, `LINK`, `CONTACT` を置く。
- Hero/Profileは、左に大きな文字情報、右に斜めトリミングの人物写真と大きな青い幾何学背景を置く。
- Profileの経歴ハイライトは、アイコン付きの横並びリストとして見せる。
- WORKは3カテゴリに分け、色を明確に割り当てる。
  - Photography: green
  - AI / Software: blue
  - Research / Technical Support: yellow
- WORKカードは、写真サムネイル、年ラベル、タイトル、短い説明で構成する。
- NEWSはカードではなく、罫線ベースのリストとして見せる。
- LINKは6つのリンクカードと、最後の横長Contact CTAで構成する。
- 右側やセクション端に、大きな色面やドットパターンを入れて商業的なポップ感を出す。

調整する要素:

- 顔写真は本人の正式写真に差し替える。
- 架空人物写真は使わない。
- 各WORK画像は、実際の撮影作例や制作物に差し替える。
- 生成画像内の英字・日本語テキストは、実装時にHTMLテキストとして再配置する。
- 装飾は画像に頼りすぎず、可能なものはCSSで再現する。

採用しない要素:

- 画像内の人物を本人として扱うこと。
- 架空の大きな企業案件や実績。
- 生成画像特有の不自然な文字、ロゴ、細部の歪み。
- 過度に巨大な装飾が本文やCTAを圧迫する構成。

## 4. サイトの目的

### 4.1 主目的

1. 自分が何者かを伝える
   - Ryo Onodera / 小野寺 諒
   - 材料工学を学ぶ大学院生
   - 写真撮影を行う人
   - AI/ソフトウェア開発に取り組む人
   - 研究・開発・制作を横断する人
2. 仕事・相談につなげる
   - ポートレート、イベント、広報写真の撮影相談
   - AIアプリ開発、業務効率化ツール、Web制作の相談
   - 研究室、学生団体、小規模事業者向けの技術支援
3. 公式リンクハブとして機能させる
   - `my-portfolio`
   - GitHub
   - 研究室HP
   - Instagram
   - LinkedIn
   - 問い合わせフォーム
4. 直近の活動を見せる
   - 撮影実績
   - 開発・研究・学習の活動
   - サイト更新
   - 登壇、受賞、掲載、修了、記事公開

### 4.2 副目的

- 氏名検索時の公式プロフィールとして機能させる。
- SNSや名刺から来た人に、活動全体を短時間で理解してもらう。
- 採用、協業、共同研究、登壇、撮影依頼の判断材料にする。
- `my-portfolio` に載せきれない人物像、経歴、仕事の入口を補完する。

## 5. 想定ユーザー

1. 撮影を依頼したい人
   - 個人、学生団体、サークル、企業、採用広報担当者など。
   - 人柄、撮影対象、対応範囲、作品例、連絡方法を確認したい。
2. AI/開発を相談したい人
   - 個人、学生団体、小規模事業者、研究室関係者など。
   - 何を作れるか、どこまで対応できるか、技術的な信頼材料を確認したい。
3. 研究・技術活動に関心がある人
   - 所属、研究室、研究領域、GitHub、学習実績を確認したい。
4. SNSや名刺から訪問した人
   - この人が何者か、どのリンクを見るべきか、直近で何をしているかを知りたい。
5. 採用・協業・登壇・取材などの関係者
   - 経歴、活動領域、実績、連絡先を短時間で確認したい。

## 6. 情報設計の基本方針

1. トップページは4セクションに絞る
   - `Profile`
   - `WORK`
   - `NEWS`
   - `LINK`
2. Profileで人物像を完結させる
   - Hero、自己紹介、肩書き、所属、経歴ハイライトをProfile内にまとめる。
3. WORKで「できること」と「実績」を統合する
   - `What I Can Do` と `Achievements` を分けず、仕事として見せる。
   - 各WORKには、カテゴリ、役割、内容、成果、関連リンクを持たせる。
4. NEWSで鮮度を出す
   - トップページでは直近3から5件に絞る。
5. LINKで外部導線と問い合わせ導線をまとめる
   - Portfolio、GitHub、研究室HP、SNS、Contactを目的別に整理する。
6. 装飾は本人情報とWORKを補助する
   - 白猫などのキャラクター要素は原則トップページの主役にしない。
   - 採用する場合は、フッターや小さなワンポイント程度に抑える。

## 7. トップページ構成

トップページは、上から順に以下の構成とする。

```text
Profile
WORK
NEWS
LINK
```

### 7.1 Header

要素:

- 左: ROロゴ
- 右: `Profile`, `WORK`, `NEWS`, `LINK`
- 端: 小さめのCTA `Contact`

要件:

- 固定ヘッダーにしてもよいが、高さは抑える。
- ロゴは手書き風にしすぎず、端正なワードマークとして扱う。
- ナビゲーションは大文字英字を基本にし、商業サイトらしい簡潔さを出す。
- モバイルではメニュー化する。

### 7.2 Profile

目的:

- 初見で「誰か」「何をしているか」「信頼できる背景は何か」を伝える。

表示内容:

- 氏名: `Ryo Onodera / 小野寺 諒`
- 肩書き:
  - `Photographer / AI Engineer / Student Researcher`
  - または `写真・AI・研究を横断する学生エンジニア`
- メインコピー:

```text
活動の価値を、写真と技術で伝える。
```

- 補足文:

```text
材料工学を学ぶ大学院生として研究に取り組みながら、人物・イベント撮影、AI/ソフトウェア開発、Web制作を行っています。
```

- プロフィール要約:
  - 大学院 / 材料工学専攻
  - 廣澤研究室
  - 東京都
  - 写真撮影
  - AI/ソフトウェア開発
  - Web制作
  - 研究活動
- 経歴ハイライト:
  - 株式会社ACES 長期インターン
  - 松尾研寄附講座 修了
  - GitHub公開リポジトリ
  - 撮影活動

CTA:

- `WORKを見る`
- `相談する`

デザイン:

- ファーストビューはProfileとして扱う。
- 大きな名前、短いコピー、本人写真または落ち着いたプロフィールビジュアルを配置する。
- 余白を大きく取り、カードを詰め込みすぎない。
- 経歴ハイライトは小さなタイムライン、数字、短いリストで見せる。
- 派手なステッカーや吹き出しは使わない。

### 7.3 WORK

目的:

- 「何ができるか」と「どんな実績があるか」を、仕事として依頼できる形で伝える。

WORKカテゴリ:

1. Photography
   - ポートレート撮影
   - SNS・プロフィール写真
   - 学生団体・サークルイベント
   - 企業イベント撮影
   - 集合写真
   - 採用広報用写真
2. AI / Software
   - AIアプリ開発
   - 業務効率化ツール
   - Webサイト制作
   - データ分析
   - GAS自動化
   - 生成AI活用支援
3. Research / Technical Support
   - 技術調査
   - データ整理
   - 研究室向け小規模ツール
   - 発表資料やWeb公開まわりの支援

表示するWORK例:

- Portrait Photography
  - 個人プロフィール、SNS、活動紹介向けの人物撮影。
- Event Photography
  - 学生団体、サークル、企業イベントの記録撮影。
- AI Workflow Tool
  - 小規模な業務効率化、フォーム集計、データ整理の自動化。
- Web / Profile Site
  - 個人・団体向けのWebサイト制作、ポートフォリオ整理。
- ACES Internship
  - AI/アルゴリズム領域の実務経験。
- Research Support
  - 研究活動、資料整理、技術検証の支援。

各WORKに入れる情報:

- タイトル
- カテゴリ
- 年
- 役割
- 概要
- 成果または提供価値
- 関連リンク
- 画像またはサムネイル

UI:

- `Featured Work` として大きめの2から3件を見せる。
- その下に小さなWORKリストまたはグリッドを置く。
- 写真・開発・研究を色で分ける場合も、彩度は抑える。
- 商業案件に見えるよう、年、カテゴリ、役割を明記する。
- 架空情報を使う場合は、現実的な範囲の仮データにする。

### 7.4 NEWS

目的:

- 現在も活動していることを伝え、プロフィールに鮮度を出す。

表示内容:

- 直近3から5件のニュースを表示する。
- 日付、カテゴリ、タイトル、短い説明、任意リンクを持たせる。

カテゴリ例:

- `Photography`
- `Engineering`
- `Research`
- `Learning`
- `Website`
- `Announcement`

表示例:

```text
2026.05.09 / Website
プロフィールサイトのトップページ方針を更新

2026.04.20 / Engineering
個人開発ツールをGitHubに公開

2026.03.15 / Photography

```

UI:

- 日付を大きめに見せ、ニュースリストとして端正に並べる。
- カード型にしすぎず、罫線、余白、テキストで見せる。
- `VIEW ALL NEWS` を置いてもよい。

目的:

- 外部サイトと問い合わせ導線を、最後にまとめて提示する。

表示リンク:

  - 所属研究室と研究活動
- Instagram: `https://www.instagram.com/d_ryo_photo`
  - 写真作品と撮影活動
- LinkedIn: TODO
  - 経歴とプロフィール
- Contact: TODO
  - 撮影・開発・協業の相談

要件:

- リンク名だけでなく、用途を短く添える。
- 外部リンクであることが分かるアイコンを置く。
- Contactは大きめに扱ってよいが、LP的な巨大CTAにしない。
- `ご相談はこちら` ではなく、`撮影・開発の相談` のように内容が分かる文言にする。

## 8. デザイン方針

### 8.1 目指す印象

- モダン
- 信頼感
- 商業的
- シンプル
- 清潔
- 余白が広い
- 写真・技術・研究の横断性が伝わる
- 若さはあるが、軽すぎない
- ポートフォリオとして仕事を依頼できる雰囲気がある

### 8.2 避ける印象

- 手描き落書きが多すぎる
- ステッカーや吹き出しが多すぎる
- カードが多く、LPテンプレートのように見える
- かわいいキャラクターが主役になる
- AIツールで生成したような未来的グラデーション
- 紫、青、黒の発光系AIデザイン
- SaaSダッシュボードのような硬すぎるUI
- 写真だけが主役の写真家サイト

### 8.3 配色

- ベース: 白、オフホワイト、薄いグレー
- 文字: 黒に近いチャコール
- アクセント:
  - 青
  - 深いグリーン
  - 落ち着いたイエロー
  - 必要に応じて小さなピンク
- 多色を使う場合も、彩度は抑えて品よく使う。
- 背景全面のグラデーションは使わない。

### 8.4 タイポグラフィ

- 大きな英字セクション見出しを使う。
  - `Profile`
  - `WORK`
  - `NEWS`
  - `LINK`
- 日本語本文は読みやすさを優先する。
- 見出しは太め、本文は軽めにし、コントラストをつける。
- 手書き風フォントは使わない。
- 文字間を詰めすぎない。

### 8.5 レイアウト

- 全体は1カラムを基本に、セクション内で2カラムやグリッドを使う。
- セクション間の余白を大きく取る。
- WORKは商業案件の一覧として見えるよう、画像とテキストの比率を整える。
- NEWSはリスト形式で見せる。
- LINKは最後に整然と並べる。
- 装飾は少なく、罫線、余白、番号、カテゴリ、写真で編集感を出す。

### 8.6 画像・ビジュアル

- Profileには本人写真または本人の活動が伝わる写真を使う。
- WORKには撮影作例、Web画面、GitHub/開発の抽象サムネイル、研究活動の写真を使う。
- 画像がないWORKは、落ち着いた抽象サムネイルで代替してよい。
- 白猫などのキャラクターを使う場合は、フッターやLINK付近に小さく配置する程度にする。

### 8.7 採用デザインの具体仕様

今回の採用デザイン案は、以下の見た目を基準にする。
2026-05-09 19:05に追加された `docs/img/new_05091905/` の7枚の新デザイン案を、現時点の最新ブラッシュアップ案として扱う。

全体:

- 白背景をベースに、青・緑・黄色・ピンクの強いアクセントを部分的に使う。
- セクション見出しは `WORK`, `NEWS`, `LINK` のように太く大きく表示する。
- 見出し横に小さな日本語説明を添え、英字の強さと日本語の分かりやすさを両立する。
- 角丸カードは使うが、カードだらけにせず、罫線、余白、色面でリズムを作る。

Profile:

- 左側に氏名、肩書き、メインコピー、説明文、経歴ハイライト、CTAを置く。
- 右側に人物写真を配置し、斜めに切った写真フレームと大きな青い背景図形で印象を作る。
- 青い背景図形、黄色の差し色、緑の下敷き、白いドットパターンをHeroの主な装飾にする。
- `WORKを見る` は青い塗りボタン、`相談する` は白背景のアウトラインボタンにする。

WORK:

- 3カラム構成を基本にする。
- 左から `PHOTOGRAPHY`, `AI / SOFTWARE`, `RESEARCH / TECHNICAL SUPPORT` の順に置く。
- 各カテゴリ見出しにアイコンと太い色線を付ける。
- Photographyは緑、AI / Softwareは青、Researchは黄色で統一する。
- PhotographyとAI / Softwareは2枚程度のカード、Researchは縦長の大きなカードを採用してもよい。
- WORKカードには、サムネイル、年ラベル、タイトル、説明を入れる。

NEWS:

- 罫線ベースのリストにする。
- 各行に、色付き斜線、日付、カテゴリピル、タイトル、矢印を入れる。
- `VIEW ALL` 導線を右上に置く。
- 右端に大きなピンクの幾何学装飾を置いてもよい。

LINK:

- 2列または3列のリンクカードを配置する。
- 各カードにアイコン、リンク名、説明、矢印を入れる。
- 最後に横長の緑色CTA `Googleフォームから相談する` を置く。
- CTAはページ最下部の主導線として扱うが、LP的に過剰な巨大表現にはしない。

CSSで再現する要素:

- レイアウト、余白、見出し、ボタン、リンクカード、WORKカード、NEWSリスト。
- Hero右側の青い斜め背景、黄色の差し色、緑の下敷き。
- NEWS右側のピンク幾何学装飾。
- 単純な長方形・斜め四角形・色線・ドットパターン。
- 写真の斜めトリミングは、画像自体ではなくCSSの `clip-path` またはラッパー要素で再現する。
- ドット装飾は `radial-gradient` または疑似要素で再現する。
- アイコンは lucide-react または react-icons を優先する。

画像として用意する要素:

- Profile用の人物写真。
- WORKカード用の実コンテンツ画像6枚。
  - Portrait Photography
  - Student Event Photo
  - AI Workflow Tool
  - Profile Website Design
  - Research Data Support
  - Lab Tool Development
- OGP用の合成ビジュアルは必要に応じて別途作成する。

画像化しない要素:

- Heroの青い幾何学背景。
- 黄色・緑・ピンクの装飾色面。
- ドットパターン。
- ボタン、カード、罫線、カテゴリピル、矢印。
- テキスト入りのUI部品。

## 9. コンテンツ要件

### 9.1 必須コンテンツ

- 氏名
- 肩書き
- プロフィール写真または本人を表す画像

- Headerはシンプルにし、左にROロゴ、右に `PROFILE`, `WORK`, `NEWS`, `LINK`, `CONTACT` を置く。
- 現在地は青い文字または青い下線で明示する。
- 下層ページでは、必要に応じて `D / Modern Pop` のような小さなトーンラベルをブランド横に置いてよい。ただし装飾が主役にならないよう小さく扱う。
- 青い斜め色面、緑の下敷き、黄色の小さな差し色、ピンクの大きな斜め装飾、ドットパターンを共通装飾として使う。
- 装飾はCSSで再現し、画像化しない。写真やWORKサムネイルだけを画像として扱う。
- 各ページの下部には、相談CTAとFooterを置き、回遊と問い合わせ導線を切らさない。
- Footerは単なる著作権表示だけでなく、ナビゲーション、カテゴリ、Social / Linkを整理した情報フッターに拡張してよい。

### 17.3 トップページ

- Heroは左に大きな氏名、肩書き、メインコピー、説明文、2つのCTAを置く。
- 右には本人写真を大きく配置し、斜めトリミング、青い大きな背景色面、黄色差し色、緑の下敷き、白ドットで構成する。
- 経歴ハイライトはHero直下の横長ボックスとして扱う。
  - `ACES Internship`
  - `松尾研寄附講座 修了`
  - `GitHub公開リポジトリ`
  - `撮影活動`
- ハイライトは各項目にアイコン、短い補足、右矢印を入れ、個別ページへのクリック領域にする。
- WORKは3列グリッドで、カテゴリごとにアイコンと色線を置く。
  - Photography: 緑
  - AI / Software: 青
  - Research / Technical Support: 黄色
- トップのNEWSは罫線ベースのリストにし、カテゴリピル、日付、タイトル、矢印を配置する。
- LINKは6カード構成にし、最後に緑の横長CTA `Googleフォームから相談する` を置く。

### 17.4 Profile詳細ページ

- ページ上部に巨大な `PROFILE` 見出しと日本語サブタイトルを置く。
- 左に大きな本人写真、右に氏名、肩書き、ステートメント、説明文を置く。
- 写真エリアは青い斜め帯と緑の下敷きを使い、トップHeroと同じ世界観にする。
- `ABOUT ME` はアイコン付きの横罫線リストにする。
  - 学歴
  - 所属
  - 所在地
  - 写真撮影
  - AI / ソフトウェア開発
  - Web制作・デザイン
  - 研究活動・技術支援
- `CAREER HIGHLIGHT` は右側に縦タイムラインで表示する。
  - 年・期間
  - タイトル
  - 1行説明
- `SKILLS & ACTIVITIES` は4列で表示する。
  - Photography
  - AI / Software
  - Research
  - Web / Design
- ページ下部にContact CTAを置く。

### 17.5 WORK一覧ページ

- ページ上部に巨大な `WORK` 見出し、短い説明文、カテゴリフィルターを置く。
- フィルターは `ALL`, `PHOTOGRAPHY`, `AI / SOFTWARE`, `RESEARCH / TECH SUPPORT` を横並びにし、選択中は緑の塗りボタンにする。
- WORKカードは3列グリッドを基本にする。
- 各カードは以下を持つ。
  - 画像上部または左上のカテゴリラベル
  - 画像下部の年ラベル
  - タイトル
  - 青色の短い説明またはサブタイトル
  - 本文説明
  - 右下矢印
- 画像比率、カード高さ、余白を揃え、一覧で比較しやすくする。
- ページ下部にContact CTAを置く。

### 17.6 WORK詳細ページ

- 左上に一覧へ戻るリンクを置く。
- ページ上部は左に `WORK`、カテゴリ、年、タイトル、概要、タグを置き、右に大きなHero画像を置く。
- Hero画像は斜めトリミングと青い大きな背景色面、白ドット、緑の下敷きで見せる。
- 本文エリアは左にメタ情報テーブル、右に詳細本文を置く2カラムを基本にする。
- メタ情報テーブルはアイコン付きで、カテゴリ、年、役割、使用技術、相談CTAを表示する。
- 成果や担当範囲などの本文情報は右カラムに集約し、左右で同じ内容を重複表示しない。
- 右本文は以下のブロックに分ける。
  - 概要
  - 課題
  - 担当範囲
  - 成果
  - 使用技術
  - 関連リンク
- 成果はチェックアイコン付きリストにする。
- 使用技術は小さなタグピルとして表示する。
- 詳細下部には関連WORKを横並びカードで表示し、Contact CTAとFooterへ続ける。

### 17.7 NEWS一覧ページ

- ページ上部に巨大な `NEWS` 見出しと日本語サブタイトルを置く。
- カテゴリフィルターは `ALL`, `WEBSITE`, `ENGINEERING`, `PHOTOGRAPHY`, `RESEARCH`, `LEARNING`, `ANNOUNCEMENT` を横並びにする。
- NEWS一覧は大きな罫線リストにする。
- 各行は以下を持つ。
  - 色付き斜線
  - 日付
  - カテゴリピル
  - タイトル
  - `VIEW DETAIL`
  - 矢印
- 右端には大きなピンクの斜め装飾を置いてよい。
- NEWS一覧ページ下部にはLINKセクションと緑CTAを配置してもよい。

### 17.8 NEWS詳細ページ

- 左上に一覧へ戻るリンクを置く。
- 記事本文は左カラム、サイドバーは右カラムの2カラムを基本にする。
- 記事上部には `NEWS` 見出し、日付、カテゴリ、タイトル、タグ、Hero画像を置く。
- 本文は見出しごとに青い横線を添え、読み物ページとして整理する。
- 主な機能やポイントはチェックアイコン付きリストにする。
- 使用技術やタグはピルで表示する。
- 関連リンクはカード形式にし、GitHubやデモなどへ遷移できるようにする。
- シェア導線は小さく扱い、X、LinkedIn、リンクコピーを想定する。
- サイドバーには以下を置く。
  - カテゴリ一覧
  - 最新のNEWS
  - タグ
- ページ下部にContact CTAと情報フッターを置く。

### 17.9 LINKページ / Contactページ

- LINKとCONTACTは同じURLにしない。
  - LINKナビは `/link` に遷移する。
  - CONTACTボタンは `/contact` に遷移する。
- LINKページは巨大な `LINK` 見出しと日本語サブタイトルを置く。
- LINKページにはリンクカードをグリッドで配置する。
  - Portfolio
  - GitHub
  - Laboratory
  - Instagram
  - LinkedIn
- 各リンクカードは大きめのアイコン、タイトル、説明、右矢印を持つ。
- LINKカード内のContactカードは置かず、下部のCTAでContactへ誘導する。
- Contactページは巨大な `CONTACT` 見出しと説明文を置き、フォームを主役にする。
- Contactページ左カラムには `USEFUL LINKS` を補助導線として置いてよい。
- Contactは作成済みGoogleフォームへPOSTする独自フォームUIを優先する。
  - Googleフォームiframeをそのまま置かず、新デザイン案の白いContactカードになじむ入力フォームとして実装する。
  - 入力欄は `Name`, `Email`, `Topic`, `Timeline`, `Budget`, `Reference`, `Message` を持つ。
  - 英語ラベルだけでなく、日本語の補助ラベルを添える。
  - `Topic` は `撮影依頼`, `AI開発相談`, `研究支援`, `Web制作`, `採用・協業のご相談`, `その他` を持つ。
  - 送信後はカード内に完了メッセージを表示する。
  - 別画面で入力したい場合に備え、`Googleフォームを別タブで確認する` の外部リンクボタンを置く。
- ピンクの大きな斜め装飾はLINK / Contactページの右側背景として使ってよい。
- 下部に、撮影・AIワークフロー・研究データ支援を連想させる薄い補足ビジュアルを置いてもよい。ただし、本文やフォームを圧迫しない。
- 最下部には緑の横長CTAを再配置し、フォームへの導線を強くする。

### 17.10 実装優先度

優先度高:

- トップページHeroと経歴ハイライトの見た目を新案に寄せる。
- `/profile` をトップページから独立したプロフィール詳細ページとして実装し、ABOUT ME、縦タイムライン、Skills 4列構成へ寄せる。
- ACES、松尾研、GitHub、撮影活動の詳細ページは制作メモではなく、訪問者向けの経験説明として記述する。
- WORK一覧カードを新案の情報密度に合わせる。
- NEWS一覧の行レイアウトを新案に寄せる。
- LINKとCONTACTを別ルートとして分離する。
- Contactページに、Googleフォームへ直接POSTする独自フォームUIと別タブ導線を置く。

優先度中:

- WORK詳細ページにメタ情報テーブル、技術タグ、関連WORK横並びを追加する。
- NEWS詳細ページにサイドバー、最新NEWS、タグ、関連リンク、シェア導線を追加する。
- Footerを情報フッターへ拡張する。

優先度低:

- `D / Modern Pop` の小ラベル導入。
- LINK / Contactページ下部の補足ビジュアル。
- SNSシェアボタンの細部実装。
